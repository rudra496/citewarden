# CiteWarden — AI citation integrity forensics

**Paste any text. Every citation gets verified live against authoritative registries — or flagged as fabricated.**

Live app: https://rudra496.github.io/citewarden/ · Built for LexHack 2026 (AI × Law × Civic Tech).

## Why

Generative AI fabricates citations with total confidence, and the failures are no longer hypothetical:
in *Mata v. Avianca, Inc.*, 678 F. Supp. 3d 443 (S.D.N.Y. 2023), a federal judge sanctioned lawyers $5,000
after they filed a brief citing six court decisions that were generated by ChatGPT and do not exist
(Order ¶36). CiteWarden is the checking layer: it reads text the way a paranoid reference librarian would.

## What it checks

| Citation family | Verification path |
|---|---|
| DOIs | Live Crossref lookup → OpenAlex fallback. 404 on both = flagged as non-existent. |
| arXiv IDs | Via their registered DOI mirror (`10.48550/arxiv.*`) in OpenAlex |
| PubMed IDs | Live NLM E-utilities summary |
| CFR sections | Official eCFR structure API (part existence in the current edition) |
| U.S. reporter cites (U.S. / F. / F.2d / F.3d / S. Ct. / F. Supp.) | 464-case verified landmark database + forensic bounds & volume-era consistency |
| Case names | Landmark DB name match + documented-fabrication watchlist |
| UK acts | Verified statute list + live Wikipedia record check (`origin=*` CORS) |
| EU regulations | ELI-verified regulation list (GDPR, DSA, DMA) |

The forensic layer works **fully offline**: reporter volume ranges, reporters cited before they existed
(e.g. any `F.3d` cite dated before 1992), decision years that contradict the volume era, malformed titles,
placeholder artifacts, and same-cite/conflicting-year collisions.

## Integrity score

Green = matched a live registry or the verified database.
Amber = well-formed but unverifiable (honest uncertainty, never guessed).
Red = impossible values, watchlist hit, or the registry confirms non-existence.
Score = 100 − 100·(red/total) − 30·(amber/total), floored at 0. Transparent by design.

## Verified data & provenance

Zero-invention policy: every shipped row of data was machine-checked at build time.

- **Landmark cases (464)** — parsed from Wikipedia's curated landmark-decisions index at build time
  (`research/build_landmarks.py`), each row passing volume-bounds (1–605), volume-era consistency against
  independently documented anchor volumes, and year sanity (1791–2026). Build logs kept in `research/`.
- **UK acts (8) + EU acts (3)** — title/year and ELI identifiers confirmed against full Wikipedia articles;
  rows that could not be confirmed (EU AI Act, EU Data Act) were **dropped**, not guessed.
- **Mata v. Avianca watchlist** — the six fabricated citations transcribed verbatim from ¶13 of the
  published order (Berkeley Law archive PDF, 678 F. Supp. 3d 443), cross-checked against CourtListener
  docket 63107798 (case metadata: S.D.N.Y., 1:22-cv-01461, Judge P. Kevin Castel).
- Full log: [`docs/EVIDENCE.md`](docs/EVIDENCE.md)

## Architecture

Zero backend, zero tracking. A static PWA (vanilla ES modules + service worker) — your text stays in your
browser; only citation strings are sent as read-only queries to public registries (all verified CORS-open).
Offline mode caches the app shell and the verified databases; live checks degrade to honest amber verdicts.

```
index.html            UI
assets/js/extract.js  citation extraction (10 families)
assets/js/patterns.js offline forensics (bounds, era, watchlist)
assets/js/verify.js   live registry calls
assets/js/analysis.js orchestration + scoring
assets/js/data/       build-time verified reference data
research/             data build + verification scripts (reproducible)
tests/                19 vitest checks incl. data-integrity guards
```

## Run

```bash
npm install && npm test        # 19/19 engine + data-integrity tests
python -m http.server 8080     # serve locally
```

## Limits (stated plainly)

- Amber ≠ fake: unfindable ≠ non-existent. Only the forensic layer (bounds, eras, watchlist) and
  registry 404s assert fabrication.
- The landmark DB covers frequently-cited U.S. Supreme Court decisions; a non-match is amber, not red.
- Case-law live lookup (CourtListener) is behind a free API token and is not bundled; the shipped
  database + forensics cover the demo and most common cites.
